# طرح میزبانی بکاپ خصوصی MONO روی `api.nourotour.ir`

وضعیت فعلی: سایت روی **GitHub Pages** می‌ماند و فقط زیردامنهٔ `api.nourotour.ir` برای دریافت و نگه‌داری
فایل بکاپ MONO استفاده می‌شود.

---

## ۱) وضعیت واقعی دامنه (بررسی‌شده، نه حدس)

| مورد | یافته | معنا |
|---|---|---|
| DNS دامنه | `nourotour.ir` و `www` روی IPهای **Cloudflare** (`104.21.36.109`, `172.67.192.150`) resolve می‌شوند | مدیریت DNS دست Cloudflare است و ترافیک از لبهٔ Cloudflare عبور می‌کند |
| `api.nourotour.ir` | **هیچ رکورد DNS ندارد** (`NXDOMAIN`) | هیچ میزبان جداگانه‌ای برای این زیردامنه وجود ندارد |
| میزبانی فعلی | GitHub Pages — `cname: nourotour.ir`, `source: main /`, `build_type: legacy`, `status: built` | فقط فایل استاتیک؛ بدون PHP، بدون پردازش `POST` |
| مخزن | `mohammadnoorifar1401-a11y/Nourotour` — **public** | هر فایلی در ریشهٔ مخزن عملاً عمومی است؛ پوشهٔ «خصوصی» معنا ندارد |
| گواهی در GitHub Pages | `https_certificate.state = bad_authz`، انقضا `2026-10-28`، `https_enforced = false` | گواهی مبدأ مشکل دارد؛ HTTPS کاربران فعلاً از سمت Cloudflare تأمین می‌شود |
| کد PHP در پروژه | وجود ندارد | این پروژه هیچ‌گاه روی PHP نبوده است |

**پس پاسخ کوتاه: نه.** در حال حاضر هیچ هاست جداگانه‌ای با PHP 8، HTTPS معتبر و امکان
ذخیرهٔ فایل بیرون از `public_html` برای این دامنه وجود ندارد. تنها چیزی که هست، GitHub Pages
پشت Cloudflare است. (مالکیت پنل هاست/Cloudflare را فقط از روی حساب‌های خودتان می‌توان تأیید کرد؛
من فقط رکوردهای عمومی DNS و تنظیمات عمومی مخزن را می‌بینم.)

## ۲) دو طرح ممکن — و انتخاب پیشنهادی

### طرح A (پیشنهادی): Cloudflare Workers + R2

چون DNS از قبل روی Cloudflare است، **هیچ شرکت هاست جدیدی لازم نیست**.

```
POST https://api.nourotour.ir/backup
      Authorization: Bearer <token>   +   HMAC-SHA256 روی بدنه
        → Cloudflare Worker (اعتبارسنجی، محدودیت حجم، نام‌گذاری)
        → R2 bucket خصوصی (Public Access: Disabled)
```

- **PHP لازم نیست** — Worker همان نقش endpoint را با محیط ایزوله اجرا می‌کند.
- **HTTPS:** خودکار و معتبر (گواهی Cloudflare برای زیردامنه؛ نیازی به Let's Encrypt و دردسر
  تحریم/`bad_authz` نیست).
- **خارج از پوشهٔ عمومی:** مفهوم «public folder» وجود ندارد؛ bucket به‌صورت پیش‌فرض
  خصوصی است و فقط با توکن/امضا خوانده می‌شود. این دقیقاً همان چیزی است که خواسته‌اید.
- **هزینه:** Workers در پلن Free روزی ۱۰۰٬۰۰۰ درخواست؛ R2 ماهی ۱۰ گیگابایت رایگان و بعد از آن
  حدود ۰٫۰۱۵ دلار به‌ازای هر گیگابایت‌ماه. نکتهٔ عملی: فعال‌سازی R2 معمولاً **افزودن روش پرداخت**
  می‌خواهد، هرچند در سقف رایگان هزینه‌ای کسر نمی‌شود.
- **محدودیت:** وابستگی به Cloudflare؛ کارت بانکی بین‌المللی برای R2.

### طرح B: هاست اشتراکی PHP 8 روی زیردامنه

```
api.nourotour.ir  → A record (DNS Only / خاکستری) → IP هاست اشتراکی
POST https://api.nourotour.ir/backup.php  → ذخیره در /home/USER/nourotour-backups/
```
- گزینه‌های رایج: هاست اشتراکی cPanel/DirectAdmin داخلی (پارس‌پک، میهن‌وب‌هاست، ایران‌سرور و مشابه)
  یا هاست خارجی. هزینهٔ نمونه: سالانه از حدود چند میلیون تومان برای پلن پایه — نرخ‌ها را
  هنگام خرید از سایت فروشنده بگیرید.
- **مزیت:** کنترل کامل، پشتیبانی فارسی، امکان اجرای Cron، آشنایی بیشتر تیم.
- **ریسک اصلی:** در هاست اشتراکی، `open_basedir` اغلب نوشتن بیرون از `public_html` را
  می‌بندد. باید *قبل از خرید* کتباً تأیید بگیرید.
- اگر مجبور شدید داخل webroot ذخیره کنید: پوشه با نام تصادفی، `.htaccess` با
  `Require all denied`، فایل‌ها با پسوند غیرقابل‌اجرا (`.bin`/`.bak`) و در حالت ایده‌آل
  رمزگذاری‌شده با کلید سمت کلاینت.

> اگر بخواهید هر دو را داشته باشید، طرح A را برای بکاپ خودکار انتخاب کنید و طرح B را فقط
> اگر به PHP برای کارهای دیگر (پنل مدیریت، CRM) نیاز دارید اضافه کنید.

### چک‌لیست پرسش از فروشندهٔ هاست (طرح B)

1. نسخهٔ PHP: ۸٫۱ یا بالاتر، با `PDO`/`openssl`/`mbstring`.
2. `file_uploads = On`، مقدار `upload_max_filesize` و `post_max_size` (حداقل ۶۴ مگابایت).
3. اجازهٔ نوشتن در مسیری بیرون از `public_html` و محتوای `open_basedir`.
4. صدور خودکار SSL (Let's Encrypt/AutoSSL) برای **زیردامنه** و امکان افزودن زیردامنه.
5. Cron jobs و محدودیت تعدادشان.
6. سیاست پشتیبان‌گیری خود هاست و بازهٔ نگه‌داری.
7. امکان تعیین `Content-Type` و غیرفعال‌کردن اجرای PHP در یک پوشه.

## ۳) طراحی امن endpoint (مشترک بین دو طرح)

- **HTTPS اجباری**؛ هر درخواست `http` با ۳۰۱ به `https` یا بهتر، رد شود.
- **توکن تصادفی ۲۵۶ بیتی** در هدر `Authorization`؛ مقایسه با `hash_equals`.
- **HMAC-SHA256** روی `timestamp + body`؛ پنجرهٔ زمانی ۵ دقیقه برای جلوگیری از replay.
  کلید فقط در سمت سرور/Secret ذخیره می‌شود، هرگز در `index.html`.
- **نام فایل را سرور می‌سازد** (`mono-YYYYMMDD-HHMMSS-<random>.bin`)، هرگز از ورودی کلاینت.
- **محدودیت نوع و حجم**؛ رد `php`, `phtml`, `htaccess`, `svg`, `html`.
- **نرخ محدودیت** (مثلاً ۱۰ درخواست در دقیقه به‌ازای توکن).
- **لاگ بدون راز:** فقط زمان، حجم، نتیجه؛ نه توکن و نه محتوا.
- **چرخش و نگه‌داری:** مثلاً ۳۰ نسخهٔ روزانه + ۱۲ نسخهٔ ماهانه؛ حذف نسخه‌های قدیمی با Cron/Worker Cron.
- **بازیابی آزمایشی:** یک بار در ماه یک بکاپ را در محیط تست restore کنید — بکاپی که تست نشده بکاپ نیست.

### گام‌های DNS
1. در Cloudflare → DNS: رکورد `A` با نام `api` به IP هاست (طرح B، حالت **DNS Only**) یا
   رکورد `AAAA/A` ساختگیِ `100::` برای اتصال Worker (طرح A).
2. در طرح B صبر کنید AutoSSL صادر شود، سپس `https://api.nourotour.ir/health` باید
   `{"ok":true}` برگرداند.
3. `api` را از `robots.txt` و از `sitemap.xml` دور نگه دارید؛ نیازی به ایندکس ندارد.

## ۴) کاری که از سمت سایت انجام می‌شود

- دکمهٔ جدید در پنل مدیریت: «ارسال پشتیبان MONO به سرور».
- محتوای بکاپ: خروجی JSON تنظیمات + نسخهٔ فشردهٔ سورس MONO (در حال حاضر
  `MONO-v1.7.0-source.zip` با ۱۰۷ فایل و حدود ۴۲۷ کیلوبایت) — بدون توکن، بدون داده‌های شخصی.
- **توکن هرگز در کد صفحه ذخیره نمی‌شود**؛ اگر ارسال از مرورگر لازم است، Worker نقش واسط را
  بازی می‌کند و توکن سمت سرور می‌ماند. آپلود دستی از پنل هاست/داشبورد R2 هم گزینهٔ ساده‌تری است.
